# s2isp — 项目计划

## 1. 目标

> **让 2011–2017 年 Apple Mac 内置的 Broadcom S2 FaceTime HD 摄像头（PCI `14e4:1570`）
> 在 Linux 上工作，且最终产物中不包含任何 Apple 二进制、不包含任何第三方驱��代码。**

分解成两个可独立交付的产物：

| 产物 | 说明 |
|---|---|
| **自研 ISP 固件** (`fw/`) | ARM 二进制，运行在芯片的 ISP 处理器上。替代 Apple 的 `firmware.bin`。 |
| **自研主机驱动** (`driver/`) | Linux 内核模块。替代 [patjak/facetimehd](https://github.com/patjak/facetimehd)。 |

## 2. 非目标

- 不追求兼容 Apple 的 410 条 CISP 命令全集，只实现出图所需的子集
- 不追求与 Apple 画质逐像素一致；目标是**正确可用**
- 不支持 1570 以外的其它 S2 变种（除非顺带就能支持）
- 不做多摄像头 / 多通道并发

---

## 2b. 画质与性能目标（追加需求）

> 需求：驱动要把这颗摄像头的性能榨干 —— 拍照清晰度与视频清晰流畅度都要顶尖。

### 先看清天花板在哪

社区驱动只暴露了 **7 个** V4L2 控制项，且把分辨率**硬编码**在 1280×720：

```c
#define FTHD_MAX_WIDTH  1280
#define FTHD_MAX_HEIGHT 720
```

而 ISP 实际提供 **410 条 CISP 命令**，画质控制面远未被使用：

| 类别 | 命令数 | 代表命令 |
|---|---|---|
| AE（自动曝光） | 80 | `AE_AGC_PARAM_SET`、`AE_METERING_MODE_SET`、`AE_PSEUDO_Y_WEIGHT_SET` |
| 色彩 / AWB | 71 | `AWB_2D_CCM_SET`、`AWB_X_TO_CCT_LUT_SET`、`AWB_HISTOGRAM_WEIGHT_SET` |
| AF（对焦） | 38 | `AF_FOCUS_MODE_SET`、`AF_PEAK_TRACKING_ENABLE`、`AF_WINDOW_WEIGHT_SET` |
| 锐化 / 降噪 | 14 | `SHARPNESS_SET`、`TNR_MODE_SET`、`TNR_AVERAGE_FRAME_COUNT_SET` |
| 缩放 / 裁剪 | 7 | `SCALER_CROP_SET`、`SCALER_SHARPNESS_SET` |
| HDR | 2 | `AUTO_HDR_HISTOGRAM_ENABLE` |

**关键判断：命令集里大量是「下发系数」（`*_COEFF_SET` / `*_MATRIX_SET` / `*_WEIGHT_SET`）
而非「做像素运算」，推断像素级处理在 S2 的定功能硬件里，固件只负责配置。**
这条假设（计划中的 A2）直接决定自研固件的工程量级别。

### 追加的成功标准

| # | 标准 | 判定方式 | 阈值 |
|---|---|---|---|
| **S8** | 解析度 | 枚举并支持传感器的**最大原生分辨率** | ≥ 1280×720 且不限于此 |
| **S9** | 锐度 | 分辨率标定靶上的 MTF50 | ≥ 传感器理论值的 90% |
| **S10** | 色彩 | ColorChecker 24 色块的 ΔE | 平均 ΔE < 5 |
| **S11** | 噪点 | 暗场（ISO 等效高增益）下的 σ | 多帧降噪后 σ 降低 ≥ 50% |
| **S12** | 流畅度 | 720p30 连续采集 | 300 秒零丢帧 |
| **S13** | 延迟 | 曝光到主机拿到帧 | < 60 ms |
| **S14** | 控制面 | 暴露并验证 ISP 画质参数 | ≥ 30 个 V4L2 控制项，且锐化/降噪/AWB 参数能实测改变图像指标 |

### 画质工作流 W（与 M1–M6 并行推进）

| 步骤 | 内容 | 产出判据 |
|---|---|---|
| **W1** 能力测绘 | 问 ISP 传感器支持哪些 mode / ���大输出尺寸；打通 SCALER_CROP 通路 | 传感器真实上限被记录 |
| **W2** 控制面 | 把 410 条 CISP 命令中可用的部分映射成 V4L2 controls | ≥ 30 项 |
| **W3** 标定 | 自研标定数据（CCM / LSC 网格 / 黑电平 / 噪声模型）替代 Apple set file | S9/S10/S11 达标 |
| **W4** 零拷贝 | DMA buffer 池、队列深度、消除多余拷贝 | S12/S13 达标 |
| **W5** 拍照路径 | 全分辨率单帧 + 静止场景多帧合成降噪 | S11 达标 |

### 必须诚实面对的矛盾

「不用第三方二进制」与「画质顶尖」之间存在真实张力：

- **用 Apple 固件 + 我们的驱动** → 立刻能用上 410 条命令与 Apple 的传感器标定，
  画质天花板很高；但依赖 Apple 二进制，**不满足本项目目标**
- **用自研固件** → 不依赖任何外部二进制；但必须自己实现 ISP 流水线
  （demosaic / AWB / 降噪 / 锐化 / LSC）并自己标定

**路线安排**：两阶段并行推进。
第一阶段（用 Apple 固件）先把**驱动侧**的能力全部榨干 —— 控制面、零拷贝、拍照路径，
顺便把 Apple 的实现当作**参照实现**来量化我们自研版本要达到的指标；
第二阶段（自研固件）逐项对齐并超越。

**画质能否追平，取决于假设 A2 是否成立**（像素运算在定功能硬件里 vs 必须自己复刻算法）。
这正是 M1 / M3 的实验设计目的。

## 3. 成功标准

全部满足才算完成。每条都必须是**二值可判定**的。

| # | 标准 | 判定方式 | 阈值 |
|---|---|---|---|
| **S1** | 自研固件 + 自研驱动从干净 checkout 可构建 | `make all` 退出码 | 0，且无第三方源码引用 |
| **S2** | 固件加载后完成握手 | 驱动日志出现自研固件发布的通道表与 magic | 通道数 ≥ 1，magic 值匹配 |
| **S3** | 取得传感器原始帧 | 抓一帧 RAW，统计像素分布 | 非全黑/全白，方差 > 阈值，帧尺寸符合传感器输出 |
| **S4** | 输出可用图像 | 抓一帧 YUV 解码为图，人工 + 自动双重判定 | 自动：动态范围 > 50、饱和度 > 0.15；人工：可辨识场景 |
| **S5** | 曝光可控且 AE 收敛 | 改曝光时间，亮度单调变化；AE 模式下亮度收敛 | 单调性 100%；收敛误差 < 15% |
| **S6** | 产物无外部依赖 | 对发布 tarball 做二进制/源码审计 | Apple 二进制 0 个；第三方驱动代码 0 行 |
| **S7** | 可复现 | 全新 clone → 文档命令 → 摄像头工作 | 从零到出图 ≤ 1 小时 |

### S6 的审计方式（客观，不靠声明）

```
# Apple 二进制：无 .bin/.dat/未剥离 ELF，且无已知 Apple kext 哈希
sha256sum <所有文件> | grep -f apple-firmware.sha256        # 必须 0 命中

# 第三方驱动代码：无 patjak/facetimehd 的特征符号
grep -rnE 'fthd_|facetimehd|FTHD_' driver/ fw/               # 必须 0 命中
```

## 4. 验证协议

每个里程碑都必须有一个**可执行的检查脚本**，而不是人工判断。

```
tools/check.sh <milestone>    # 跑该里程碑的全部判定，返回 0/1
```

设计原则：
- **客观优先** —— 能用数字判定的绝不用眼睛
- **真机** —— 所有验证都在这台 2013 rMBP 上跑
- **可重复** —— 每次判定前重新加载模块、清 dmesg，避免状态污染

每个里程碑有明确的**交付物**和**闸门条件**。闸门不通过就停下来重新评估，

### M1 ★ 自研固件启动 — **项目分水岭**

| | |

## 6. 风险与终止条件

诚实列出可能让项目失败的原因，以及对应的应对。

| 风险 | 影响 | 应对 / 终止条件 |
|---|---|---|
| ISP 启动协议有我们没识别的硬件依赖 | M1 卡住 | 3 轮尝试仍不通 → 停止，重新评估是否存在绕过 ISP 的硬件通路 |
| S2 的 ISP 处理单元无法绕过，必须复刻完整算法 | 工作量从月级变成年级 | 优先验证"只下发系数、像素运算在硬件里"的假设（见 §7） |
| 传感器型号差异大 | M3 泛化难 | 先只支持本机这一颗（1871），其它型号后置 |
| 真机只有一台 | 回归测试受限 | 固件/驱动都做成可回滚，先建立"能跑"的基线再改 |

**明确的终止条件**：若 M1 在 3 轮独立尝试后仍无法握手，
则本项目**不成立**，应转向「编写我们自己的 ISP 固件在别的平台上验证」或「仅重写主机驱动、
固件仍用 Apple 的」这两条退路。

## 8. 当前状态

| 里程碑 | 状态 |
|---|---|
| M0 工具链与规格 | ✅ 通过（`tools/check.sh m0`） |
| M1 自研固件启动 | 🔶 **核心证据已拿到**：我们自己的 ARM 固件能在 ISP CPU 上执行 |
| M2–M6 | ⬜ 未开始 |
| W1–W5 画质工作流 | 🔶 需求已明确，能力测绘待做 |

### M1 已完成的部分

- ✅ 确认 ISP CPU 从 **DDR 偏移 0** 启动，向量表必须在镜像偏移 0（否则 CPU 跳飞）
- ✅ 写出**完全位置无关**的 ARM 固件（`fw/probe.S`），能在 ISP CPU 上执行并往 DDR 写标记
- ✅ 实现数据访问异常处理程序（ARMv7 异常帧布局），使扫描能跨越未映射区域
- ✅ 确认主机侧观测通道可靠（ISP 寄存器窗口能读回驱动写入的值）
- ✅ 拿到 5 阶段握手规格与 411 条命令表

### M1 待解决

- ❌ **ISP CPU 用什么地址访问 ISP BAR4 的寄存器**（主机物理 `0xb0800000`）
  - 已排除：`0xb0800000`（读出的是 PCIe 总线错误签名，非真实数据）
  - 扫描受限：未映射读有**长超时**，全空间盲扫不可行
  - 下一步：改用**内容寻址**——从参考固件中定位它访问这些寄存器的指令序列，
    反推基址；或用「读到非错误签名」的判据做定向扫描

### 意外收获（对项目很重要）

**上游驱动缺少正确的关停路径。** `fthd_hw_deinit()` 只往 `ISP_REG_41020` 写 0，
不对 S2 芯片做电源周期。结果是：

1. 热卸载模块后 ISP CPU 仍处于已启动状态
2. 再次加载时不会从复位向量重新取指 → `Init failed! No wake signal`
3. **用 Apple 原厂固件也一样失败** —— 硬件进入不可用状态
4. S3 挂起/恢复**不能**修复（设备保留内部状态）

唯一有效的恢复：让 PCI 设备彻底消失再重新枚举：

```bash
modprobe -r facetimehd
echo 1 > /sys/bus/pci/devices/0000:02:00.0/remove
echo 1 > /sys/bus/pci/rescan
```

已封装为 [`tools/recover-camera.sh`](../tools/recover-camera.sh)。

→ **我们的驱动必须实现真正的 S2 电源周期**（Apple 的 kext 有 ACPI 路径的
`DisableS2Chip`/`EnableS2Chip`，Linux 驱动完全没有）。这是 M2 的硬性要求。

已完成的关键结论见 [`notes/`](notes/)。

## 9. 工作方式上的自我约束

1. **不复制他人代码。** 所有实现从零编写。已有驱动只作为"协议行为参考"，
   且其结论都要用**运行时观测**独立复核后才采信。
2. **区分「知识」与「代码」。** 从 Apple 固件里读出的协议结构是关于硬件接口的知识；
   我们的实现必须是自己的。固件里的 ARM 机器码不会被复制 —— 我们写自己的固件。
3. **每个结论都要能被复现。** 结论写在 `notes/`，附上产生它的命令。
4. **不确定就说不确定。** 宁可标注"待验证"，不要写成结论。
